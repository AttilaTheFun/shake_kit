- **One renewal at a time across apps sharing a sign-in**: `GitHubCredentials(…, renewalLock:)` takes a `RenewalLock` every app on the store shares (`FileRenewalLock`: an exclusive `flock` on a file in an app group's container, let go by the system if its holder ends). Under it the store is read again, the token renewed, and the renewed token kept before the lock is let go, so two apps never spend one refresh token, and the one that waited takes the other's renewal.
- **A shared sign-in, named by the host's Info.plist** (`GitHubSharedSignIn`: `GitHubSharedClientID`, `GitHubSharedKeychainGroup`, `GitHubSharedLockGroup`, and optionally `GitHubSharedKeychainService`, stamped by CI): its store in the shared keychain group, its renewal lock in the lock group's container, and `credentials(scope:)` on them. And **the scope a token was granted** (`GitHubToken.scope`, from GitHub's answer; `covers(_:)`, where `repo` covers `public_repo`), so an app can fall back to its own sign-in when the shared one's reach is too small.
